# Architecture

Two targets, one repo:

```text
[Apple Watch app] ──WC (Bluetooth)── [iPhone companion app] ──wss── [OpenAI Realtime]
```

## Watch app (`WatchGPT/`)

Captures and plays audio. Holds no networking, no API key.

- Mic capture via `AVAudioEngine` at 24 kHz PCM16 mono.
- Sends each chunk to the iPhone via `WCSession.sendMessageData`.
- Receives audio chunks back via `sendMessageData`, plays through `AVAudioPlayerNode`.
- Receives `[String: Any]` control messages (`ready`, `speechStarted`, `userTranscript`, `assistantTranscriptDelta`, `assistantTranscriptFinal`, `error`, etc.) via `sendMessage`.
- Renders the phase state machine and transcript.
- Keeps active sessions alive with `WKExtendedRuntimeSession`, an active audio engine, and a lightweight HealthKit `HKWorkoutSession` started only after the user begins a voice session. The display can still dim, but workout session mode is the supported way to keep watch execution alive wrist-down.

## iPhone companion (`WatchGPTPhone/`)

Holds the OpenAI Realtime WebSocket and the API key.

- API key from Keychain (Settings screen) → bundle default (`WATCHGPT_OPENAI_API_KEY` from xcconfig). A one-time migration removes the legacy plaintext `UserDefaults` value.
- On `start` from watch, opens `wss://api.openai.com/v1/realtime?model=<selected-model>` with `Authorization: Bearer <key>`. The current GA endpoint does not use the old `OpenAI-Beta` header.
- Fast Mode defaults to `gpt-realtime-2.1`, with `gpt-realtime-2.1-mini` selectable. `session.update` configures 24 kHz PCM16 in/out, the selected realtime voice and transcription model, bounded output, and either semantic VAD with the selected eagerness or manual turn detection for push-to-talk.
- Forwards watch audio to OpenAI as `input_audio_buffer.append` (base64 PCM).
- Forwards OpenAI audio deltas to the watch inside the session-scoped binary audio envelope over `sendMessageData`.
- Forwards transcripts and state events to watch as `[String: Any]` messages.
- Think Mode skips the Realtime socket and uses a chained voice pipeline: local peak/silence detection on the phone, Audio Transcriptions (`gpt-transcribe`), Responses API (`gpt-6.1-sol` by default, with Astra, Terra, and Luna selectable), then `gpt-audio-1.5` speech with PCM output back to the watch.
- Socket writes use a bounded ordered queue. Turn duration, session duration, response output, and tool calls have explicit limits; session-scoped tasks are cancelled during teardown.
- Transcript snapshots are persisted off the main actor by `TranscriptStore`, with debounced atomic writes to a data-protected file under Application Support.

## Shared (`Shared/RealtimeMessages.swift`)

Compiled into both targets. Defines:
- `RealtimeMessageType` — typed enum of message kinds.
- `RealtimeMessageKey` — short string keys (`"t"` for type, `"x"` for text, `"s"` for session ID, `"q"` for sequence, and `"a"` for automatic turn detection).
- `RealtimeMessage.encode(_:payload:)` / `RealtimeMessage.type(of:)` helpers.

Control and audio envelopes carry a session UUID plus monotonically increasing sequence numbers so stale delivery from an earlier session can be rejected. Audio data still uses the dedicated `sendMessageData` channel rather than a property-list dictionary.

## API key handling

Resolution order on the iPhone:
1. Keychain override (from Settings UI).
2. Bundle default `WATCHGPT_OPENAI_API_KEY` from `WatchGPTPhone/Config/LocalSecrets.xcconfig` (gitignored, generated by `npm run configure:phone`).

On launch, a legacy `UserDefaults` override is migrated to Keychain and scrubbed. The watch never receives or stores the key.

## Model policy

- Fast voice: `gpt-realtime-2.1` default; `gpt-realtime-2.1-mini` economy option.
- Think reasoning: `gpt-6.1-sol` default; `gpt-6-astra` maximum-capability, `gpt-6.1-terra` fast, and `gpt-6-luna` economy options.
- Transcription: `gpt-transcribe`, OpenAI's recommended model for completed audio files.
- Think speech: `gpt-audio-1.5` through Chat Completions, returning PCM16 audio.
- Transcript metadata: `gpt-6-luna`, with a small output budget.

Fast Mode stays on GPT-Realtime 2.1 and its mini variant because the app currently uses the Realtime API protocol; GPT-Live 1 requires a separate migration to its `/v1/live/sessions` protocol.

The selectable aliases are intentional for a personal app that can adopt current behavior immediately. If reproducible model behavior becomes more important, pin tested model snapshots in `PhoneConfiguration`.

## Threat model

This is a **sideload-only personal build**. The iPhone holds your live API key. Anyone with access to the iPhone app bundle can extract the key. Do not distribute a build.

## Why the iPhone is required

watchOS does not allow third-party apps to open arbitrary outbound TLS WebSockets. We verified this with three transports — `URLSessionWebSocketTask`, `URLSession` with `waitsForConnectivity = true`, and `NWConnection` with `NWProtocolWebSocket` — all fail (`URLError -1009 notConnectedToInternet`, `cancelled`, or `POSIXErrorCode 50 ENETDOWN`) on a fully-autonomous Apple Watch Ultra with active cellular and Wi-Fi, while Apple's own apps simultaneously pass data through privileged paths a third-party app cannot use. A public WSS echo (`wss://echo.websocket.events`) also fails to handshake from the watch standalone — confirming this is a watchOS network restriction, not anything specific to OpenAI. The iPhone companion sidesteps this by holding the WebSocket itself.

## Voice quality target

- semantic VAD decides when the user is done speaking in hands-free mode (server-side).
- assistant audio streams back as 24 kHz PCM and starts playing as soon as the first delta arrives.
- speaking interrupts the assistant; `interrupt_response: true` lets OpenAI cancel the response.
- `marin` is the default voice.
